# Q4 发现调度：首轮独立消融

2026-09-11，起点 `18e1c5c`。MEC 继续作为正式默认清除站位；NCCP、segment_entry、Clearance Gap 停止调参，仅保留论文消融与技术边界证据。state-restoring bridge 单独限时审计，若无法建立严格耦合则停止实现。

## 问题与边界

问题是：保留全部45个保证节点与每节点全部尚未清除频道的扫描，能否仅调整剩余节点顺序和频道顺序，降低最后一个真实源的首次发现时间及整局耗时？真实源数量、位置、类型与未发现频道身份只供事后评估，策略不得访问。

固定覆盖点、CPU FP64硬域、no_signal语义、MEC触发、diagnostic v1主评分/参数、光学兜底顺序与粒子数。保持发现与定位的原竞争公式，不改变提前终止条件，不跳过已发现但未清除频道。Q3无行为变化。新增两个选项默认均关闭。

## 代码事实与两项候选

现有 `geometry.route` 已有最近邻和三轮2-opt。`Solver.run` 只在每次整点扫描后重排剩余路线；中间定位/清除改变机器人位置后，仍使用上一次的缓存首节点。

1. **refresh_after_localize**：每次原定位分支返回后，用新位置对全部剩余节点调用原route。比较两条完整开路径的移动距离；仅严格变短才替换原缓存顺序。节点坐标、集合、数量不变。该判据保证当前同一状态的计划完整路长不增加，不能保证下一首跳、发现前缀或被定位打断后的整局更短。
2. **unknown_first**：仍将当前频道放首位，其余频道稳定分成尚未发现、已发现未清除两组；已清除频道仍按原流程跳过。每点原来要测的频道一个不少。当前P4在整个频道批次结束后才重做定位竞争，除了near原地清除；所以该变化主要测试首次发现时刻和批次结束频道，不预称减少每点测量或切频数量。

首轮做2×2消融：原配置、仅刷新节点、仅未知频道优先、两者组合。不调整系数，不据开发结果继续试参数。

## 指标与复核

| 指标 | 定义/单位 |
|---|---|
| last_source_first_seen_s | 场景真实源各自首次direction/near的最晚返回时间，秒；未全部发现则null |
| last_source_first_seen_per_source_s | 上项除以真实源数，仅供跨场景比较 |
| final_discovery_measure_s | 最后一次保证节点扫描测量的返回时间，不等于最后真实源首次发现 |
| post_last_seen_discovery_s | 全部源均已出现后继续用于discovery的时间；是事后诊断，不授予策略提前停止权 |
| mean_time_per_source | 整局虚拟秒/真实源数，报告均值、P50/P95/P99/max及逐例胜平负/最大退步 |
| integrity | 全清除、异常、协议失败、超时、硬域包含性、清除证书、45节点和每点频道覆盖完整性 |

逐节点检查全部未清除频道恰测一次，45坐标集合恰等于原coverage；策略采用MEC且候选只改变两项调度字段。原始row、trace、scene、配置和源码SHA互相绑定。最后发现时间同时由原始actions和target first_seen记录复算，truth只用于选择真实频道集合。主要判断同时看最后发现、整局和尾部，不因单一均值好看就修改默认。

## 术语与保证

“未知频道”指当前尚无direction/near的频道，不代表其中必有源。“剩余节点”指原45节点中尚未完成整点扫描者。保证的是有限节点/频道覆盖义务保留；执行在现实/虚拟预算下能否完成仍由完整案例验证，不把局部路长筛选解释成普遍整局支配。
