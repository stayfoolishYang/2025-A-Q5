# Q4 最终 HTTP 入口

`official.py` 装配与离线 `run.py` 一致的21点、R12、失败计数修正和C-TSPN策略；使用修复后的几何函数及具有完整动作账本的Client。导入模块、显示帮助和不带`--execute`的调用不会发送请求。运行前由操作者在官方模拟器中选择正确的问题4正式或演练模块，核对案例编码并等待接口就绪。机器人接口不提供模式查询，本入口的`--mode`只是操作者声明，不能自行证明运行类型。

命令模板（尖括号内容由操作者实际填写）：

```text
python -B code/q4betterv3/official.py --robot-id <队号> --case-code <案例编码> --mode formal --output results/q4_formal_1 --execute
```

演练将`formal`改为`practice`；默认服务为公开协议中的本机回环地址，如端口已调整可传`--base-url http://127.0.0.1:<端口>`。每次使用新输出目录；入口使用自身目录中的系统文件锁阻止其两个副本同时发送动作。它不能阻止其他独立程序误发请求，运行时只保留一个发送程序。

程序输出动作、响应、CT桥接事件、跟踪状态与结果。`full_clear_verified`固定为false，因为正式接口不公开源总数；不能把算法退出或清除数自动当作外部验证的全清结论。演练界面核对、正式结果表及官方原名加密日志需由真实记录另行归档。运行生成的wire日志含传入队号，仅保存在操作者选择的目录，公开分享前应另做身份处理。

此次仅用替换URL传输函数的mock测试，没有打开socket或访问官方接口。3个完整策略mock场景及重试、拒绝、频道与限时契约通过，详见`verification/REPORT.md`。这证明本地装配契约闭合，不声称已在官方正式窗口完成验证。
