# A26-06-FULL-v1 静态交叉审查记录

范围：Stage06 全量自动服务器入口及它必需的既有事件重积分修复。数学规格 A26-04-v2 未变；不执行本地 pytest、项目模块、求解、GPU 探测或依赖安装。实现阶段条件 Gate 不替代服务器运行证据。

父代理集成 CLI、preflight、campaign runner、官方文档/状态和发布；3 个现有有界子代理分别实现纯计划、数值分析、结构比较，并交叉检查相邻接口。没有并行重复求解，也没有自动进入 Stage07。模型/effort 的实际后端身份未独立核验，本记录不声称变更了父任务模型。

| 静态发现 | 处理及保留的验证要求 |
| --- | --- |
| 新 full 计划可能被旧 preflight 当作 RunConfig 拒绝 | 识别 CAMPAIGN_PLAN，纯配置展开；显式设备覆盖同步用于预检与强制 GPU 测试 |
| 前序动作重做时下游可能沿用旧证书 | ActionStore 缓存纳入前序依赖及实际产物哈希；新尝试目录也改变依赖，C 参考时间进入 B 分析身份 |
| 成功 JSON 可能掩盖非零退出或超时 | 优先判定子进程退出状态；保留部分记录，不能冒充本次成功 |
| 初始化目录存在但尚无检查点时永久无法 resume | 保留遗留目录，新尝试使用独立目录从初值开始 |
| 事件细步长从很早的稀疏检查点起作用 | 从真实检查点按原策略桥接到局部开始位置，再保存真实 checkpoint 并进行局部细化；记录分段来源、步数和共用预算 |
| 一次延长最大严格等待尾段容易耗尽比较点预算 | 初始只覆盖实测事件右端附近，后续根据实测余量在完整源上的阈值扫描按需延长；不调整误差阈值 |
| 余量增大后旧报告轨迹不足以覆盖新严格时刻 | 有界闭环中补齐实际事件/当前轨迹覆盖，重建证据，余量变化继续下一轮；不改写指纹伪装同一轨迹 |
| 缩小半径时按同一材料坐标比较会偷换实际位置 | B/C 和敏感性比较使用共同实际半径域、分段点并集及二次差驻点；各路线 G 使用各自完整域 |
| 包装过程中锁文件与自引用完成状态混淆 | ZIP 排除锁文件；保留打包前科学证据快照，最终回传状态以包外汇总为准；无包不能得到全量成功退出码 |

新增服务器测试覆盖纯计划去重/角色/硬件、缓存与恢复/预算、失败阻断、分析覆盖/余量/导出条件、B/C 和实际半径比较、检查点桥接。它们均为 **NOT_RUN**；mock 控制流测试即使在服务器通过，也不能当作 PDE 或 GPU 精度证明。

实际静态检查脚本为 `stage06_full_static_check.py`，仅使用标准库 AST/JSON/TOML/哈希，不导入项目。最新检查结果见 `stage06_full_static_checks.json`。仓库打包另检查 owned-folder 范围、文件字节与暂存 blob 一致、原件/authority 不变、发布后本地 HEAD 与远端 main 相等。

限制：67 个主求解配置与14组比较为静态计划预期；事件/报告/重试另计。48h会话和300s打包均是有限上限，不是预计耗时。实际空间误差、严格余量闭合、C 参考及敏感性仍可能UNRESOLVED；不会为了生成结果表而放宽模型或验收阈值。Q1历史CPU早期层差异仍是重要未解决问题。独立物理数据缺失不因自动计算而消失。

结论：本记录只支持 **STATIC_REVIEW / SERVER_ACCEPTANCE_PENDING**；Gate06 CONDITIONAL_PASS，Stage07/08 NOT_RUN，current_best_verified=null，model_frozen=false。
