# q4betterv3：21 点 + R12 + F + C-TSPN

本目录保留用户选定的 `21r12ctf` 版本，提供独立离线运行入口。它使用冻结的 21 点坐标、R12 动态路线刷新、F 失败计数分离，以及已验证的 C-TSPN 清除点优化。原 `q4better` 和 `q4betterv2` 保持不变。

## 运行

使用 Python 3.11，在仓库根目录执行：

```powershell
python -m pip install -r q4betterv3/requirements.txt
python q4betterv3/run.py --scene q4betterv3/example_scene.json --output q4betterv3/run_output
```

每次使用新的输出目录。输出包含 `core/rows/B_0000.json`、完整动作轨迹 `core/traces/B_0000.json.gz`、CT 事件 `ct_events.json` 和本次输入/配置清单。入口默认且只启用本版本；随包使用原离线引擎，不依赖本机旧项目路径。此入口没有实现或验证官方 HTTP 接入。

验证便携入口与原实验是否一致：

```powershell
python q4betterv3/verify_release.py
```

首次运行会在 `verification_runs/` 保存案例 0、95、874 的结果，逐动作、反馈、RNG 和总时间与归档轨迹比较。已有目录不会覆盖。发布时的验证结果见 `RELEASE_CHECK.json`。

## 1000 场景验证结果

新生成 1000 个场景，对两组各运行 1000 次，固定参数、相同场景配对。

|指标|25 + R12 + CT|本版本 21 + R12 + F + CT|
|---|---:|---:|
|平均秒/源|549.455|520.384|
|P95 秒/源|725.084|678.442|
|P99 秒/源|767.248|736.896|
|最慢50局平均秒/源|754.673|712.950|
|最终全清除|1000/1000|1000/1000|

本版本平均节省 **29.071 秒/源（5.291%）**，每局平均节省 **364.292 秒**；配对 **766 胜、0 平、234 负**。最坏退步为案例95（16源），慢126.826秒/源、2029.223秒/局。不能宣称逐例优于25点方案。15源组均值改善，但P95变慢5.213秒/源，详见分组报告。

每源时间指每局总虚拟物理时间除以源数，再跨场景统计，不是逐源完成时刻；不包含规划程序真实计算耗时。两组最终均全部清除，中途失败清除尝试分别841和189次，不能由最终成功掩盖。

## 冻结源码、配置与覆盖

- `source/` 和 `offline_engine/` 从本轮 `frozen_source.zip` 按哈希提取，核心算法字节不改。
- `config_21r12ctf.json` 与1000例实验B组配置相同，F和CT均开启。
- `points21.json` 与实验冻结坐标完全相同。内部 `certified25` 选择器仅为旧接口兼容，入口在求解器和动作检查器共同使用的覆盖函数上装载实际21点；不是运行25点。
- `COVERAGE_CERTIFICATE.md` 是用户提供的连续覆盖证明报告，本次打包没有重新审计它，不声称21点是全局最小点数。
- `SOURCE_SHA256.json` 记录随包核心源、引擎、配置和坐标哈希；源码文件禁用Git换行转换。

## 证据文件

`validation/` 包含完整1000例配对CSV、2000次行级结果、检查汇总、最坏30例、图表、配置/种子清单、冻结源码归档。`scenes.zip` 包含全部1000个原始场景，可解压后逐个传给 `run.py`；`representative_traces/` 保存普通、最大退步、最大收益场景的本版本完整轨迹。完整2000份大轨迹保留于原本地实验目录，未全部重复上传。

原实验报告和冻结实验脚本中的本地路径用于历史追溯。运行此交付使用上面的便携入口；不直接运行历史 `source/` 中的实验驱动。验证指标来自真实本地离线运行，证据范围为 `LOCAL_DEV / FRAMEWORK_INTEGRATION / production_eligible=false`，不是官方隐藏场景或生产模型冻结保证。
