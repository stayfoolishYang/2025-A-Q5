# Jammers 演练生成器整函数及全部场景字段对照报告

**结论：通过生成器层面的全部字段与随机流对照。** 本次在基础库适配环境中执行原始 `GeneratePractice` 的完整调用流程，直到原函数正常返回，并将其结果与此前交付的 Python 还原版比较。518 个种子、1,036 个问题 3/4 场景，未发现字段或随机流差异。

状态为 `PASS_GENERATOR_FIELDS_WITH_RUNTIME_SUBSTITUTIONS`。这个状态明确包含基础库替代条件，不表示整个 Windows 模拟器或正式比赛场景已经通过等价验收。

## 1. 本次实际运行了什么

输入仍是同一个 `jammers-simulator.exe`：

```text
SHA-256 = 2373b9e7af83735a04309e2983eb433ec46faf7e0b8494410ce7fded2a297c27
```

当前环境为 Linux x86-64，未安装 Windows/Wine。本次没有启动 EXE 的入口、桌面框架、登录、授权、上传或其他网络流程。

对照环境从 EXE 提取选定的原始代码和静态数据，按原地址映射到一个独立进程。执行的核心路径为：

1. 原始 `GeneratePractice` 检查问题编号与默认生成/仿真参数。
2. 原始 `counterSource.next/uintN/shuffle` 构造随机流消息、维护标签计数器、执行拒绝采样与洗牌。
3. 原始生成器决定数量、频道、定向属性、位置、接收半径、朝向和误差场种子。
4. 原始 `math.Sincos` 参与坐标计算，原始整数圆盘检查控制重采样。
5. 原始 `ParseAndValidate` 控制 JSON 回读、EOF、规范化检查及后续验证。
6. 原始 `Scenario.validate` 逐项检查生成结果，原始代码设置原始数据及内容摘要字段。
7. 原始 `GeneratePractice` 正常返回；对照工具读取其返回结构和字节切片。

纳入执行区域的 13 个原始函数均在安装适配入口之后再次与 EXE 字节比较，确认原函数代码未被改写。完整清单见总结果。列表包含指针/值接收器包装函数，不代表每个包装函数在每个样本中都会执行。

此前仅做过三角函数、整数采样和洗牌的局部指令对照；本次增加了完整生成流程、原始 HMAC 消息构造、所有场景字段、原始业务校验和正常返回检查。

## 2. 两侧如何保持独立

| 原始侧 | 还原侧 |
|---|---|
| 执行从 EXE 提取的原始生成指令 | 执行之前交付的 `recovered_generator.py` |
| 原始指令决定标签内容、计数器、调用顺序、取样与场景字段 | Python 还原源码决定对应行为 |
| 场景结构通过 EXE 中的 Go 字段元数据读取 | 使用还原版独立构造的 Python 字典 |
| 对原始指令拼出的消息调用 OpenSSL HMAC-SHA256 | 使用还原版的 `hmac.digest` |
| 坐标使用原始 `math.Sincos` 机器指令 | 使用已还原的 Python 三角函数 |

原始侧 `native_oracle.py` 不导入还原版生成器、标签表或数学实现。比较程序同时导入两侧，但不会把还原侧生成的场景或随机流喂给原始侧充当结果。

SHA-256/HMAC 都是标准原语；这里没有执行原始 Go HMAC 的内部实现。两侧使用标准库计算相同算法，因此证据支持“原始消息构造与派生随机流一致”，不能据此声称审计了 Go 密码库的内部实现。

## 3. 基础库适配范围

| 被适配的依赖 | 适配行为 | 影响的结论范围 |
|---|---|---|
| 内存分配、切片增长、字符串转换、数据复制 | 提供等价的字节存储与复制；不运行 Go GC | 不验证原版内存占用、GC、OOM 与并发时序 |
| map 的查找/插入、内部随机盐 | 保持键值语义；内部盐可控 | 不验证原版 map 性能；另做盐变化不影响场景的检查 |
| `sort.Ints`、`fmt.Sprintf` | 对实际使用的整数与格式串提供标准行为 | 不验证 Go 排序内部实现或完整格式化库 |
| HMAC-SHA256、SHA-256 | 调用 OpenSSL 3 标准原语 | 不执行 Go 密码库内部代码 |
| `math/big.Int` 基本运算 | 对原始圆盘检查提供精确整数乘、加、比较 | 原始几何判定及控制流仍执行，不验证 Go 大整数内部算法 |
| JSON 编码/解码、未知字段与 EOF 支持 | 按 Go 元数据读取字段，使用 Python JSON 完成编解码 | **不能独立证明原生 Go JSON 输出字节与适配层完全相同** |
| 原始错误接口的基础比较 | 支持本次 EOF 和真实业务错误返回 | 不验证标准库全部错误包装行为 |

完整的替代入口、地址和实际调用次数均写入 `comparison_summary.json`。无法处理的调用或错误会终止进程，不会被当作成功结果继续比较。

原始 `ParseAndValidate`、EOF 判断和 `Scenario.validate` 的控制流程实际执行，但其中的 JSON 标准库是替代实现。为避免过度表述，本报告将“原始业务校验执行”与“原生 Go JSON 编解码验证”分别记录。

## 4. 输入设计与实际结果

518 个种子组成如下：

- 6 个固定字节模式：全零、全 `ff`、递增、递减、全 `aa`、全 `55`。
- 256 个单比特种子，逐个覆盖原始 256 位输入的各位。
- 256 个可复现的 SHA-256 派生种子。

每个种子分别运行问题 3 和问题 4，共 1,036 个正常场景。它们都是本地合成测试输入，不是官方真实场景种子。

| 项目 | 实际数量 | 结果 |
|---|---:|---|
| 不同原始种子 | 518 | 全部完成 |
| 原始生成器正常返回的场景 | 1,036 | 全部字段一致 |
| 逐源比较 | 13,502 个源 | 整数坐标、频道、接收半径、类型与方向一致 |
| HMAC 消息及摘要逐次比较 | 72,672 对 | 内容及顺序一致 |
| map 内部随机盐改变 | 12 个场景 | 场景保持一致 |
| 原始拒绝路径探针 | 10 项 | 全部被原始业务代码拒绝 |
| 已发现正常场景差异 | 0 | 无需修正还原版生成逻辑 |

本次样本覆盖源数量 10–16，以及 Q4 定向源数量 1–16，并出现全部源为定向源的样本。具体频数和示例种子随结果提供。样本数量有限，不是对全部 `2^256` 个种子的穷举，也不是正式比赛难度分布的统计验证。

## 5. 完整比较的内容

**场景层：** schema、规则版本、问题编号、来源、数据集版本空值、生成器版本、原始种子、误差种子、全部生成规则、全部仿真规则和源列表。

**每个源：** 频道、整数微米 x/y 坐标、整数微米接收半径、全向/定向类型、整数微度朝向或空值。比较采用精确相等，没有对坐标使用浮点容差。

**随机流层：** 原始指令传给 HMAC 的完整密钥字节、完整消息字节、32 字节摘要和调用顺序。消息中实际包含域前缀、标签、分隔符与计数器，因此这项比较能检查此前仍依赖静态分析的消息布局和随机流消耗顺序。

**返回层：** 原始生成器正常返回；生成结构、JSON 回读后的结构、规范化后的结构一致；返回场景中的 Raw 与实际返回字节切片一致；内容 SHA-256 与适配 JSON 字节一致。最后一项只对适配层的 JSON 字节成立，不等于原生 Go JSON 逐字节验收。

## 6. 确认原始校验没有被绕过

以下 10 项输入被原始生成/校验代码拒绝，错误记录在 `runtime_and_rejection_probes.json`：

| 探针 | 原始返回结果 |
|---|---|
| 问题编号 0、2、5 | 问题必须为 3 或 4 |
| 修改生成默认参数 | 不支持的生成规则 |
| 修改仿真默认参数 | 不支持的仿真规则 |
| 修改 schema | 不支持的场景或规则版本 |
| 误差种子包含非十六进制字符 | 必须为 16 位小写十六进制 |
| 源位置超过生成圆盘 | 位置越界 |
| 接收半径低于下限 | 接收半径越界 |
| 重复频道 | 频道必须唯一且严格递增 |

探针不计入正常场景的 1,036 次对照，也不代表原版全部异常处理路径已穷举。

## 7. 对此前结论的更新

此前尚未整函数核验的这些内容，现在获得了完整生成流程的字段/随机流对照支持：

- 32 字节原始种子的直接使用方式及域前缀、标签、计数器格式。
- 数量采样、频道选择、排序和 Q4 定向频道选择。
- 半径 1770 米生成圆盘和 30 米外围无源区域。
- 接收半径及定向朝向的整数单位与取值方式。
- 噪声种子派生以及 Q3/Q4 相同原始种子下的相关行为。

本轮未发现生成器差异，因此没有为了获得通过而修改此前还原源码。原始版本与对照版本源码指纹见 `provenance.json`。

## 8. 仍不能宣称的内容

1. **完整 Windows 模拟器等价。** 本次没有运行 Wails 界面、本机 HTTP 生命周期、计时、日志和其他完整应用流程。
2. **原生 Go JSON 输出逐字节一致。** JSON 库在适配范围内，完整原生序列化还需要真实 Go/Windows 环境或对应原始导出数据核验。
3. **正式比赛场景复现。** 本次运行的是客户端演练生成器，没有取得正式场景种子或验证服务端生成方式。
4. **官方演练实测记录对照。** 本次原始侧来源是 EXE 的原始生成指令及静态参数，没有官方运行后导出的真实场景作为第三方记录。
5. **任意平台、任意 EXE 版本或所有种子都经过实测。** 对照工具严格绑定本报告的 EXE 指纹，测试范围为明确列出的输入。

现在可以据证据表述为：**原版演练生成算法的整函数流程与全部输出字段，在已声明的基础库适配条件下通过对照。** 原始码路径不确定性已显著缩小；剩余限制集中在完整应用环境、原生标准库行为和正式场景数据。
